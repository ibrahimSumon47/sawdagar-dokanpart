# Decisions

- 2026-10-28: Start Phase 0 with a static, bilingual landing page and workspace quality gates. It does not require data loading, so no skeleton, empty state, or retry state is shown for this static content. Interactive localization and the design system remain Phase 1 work.
- 2026-10-28: Use ESLint 9.39.5 rather than ESLint 10 because the current Next.js plugins declare support only through ESLint 9; revisit when their peer ranges support the newer major version.
- 2026-10-28: Check formatting for web application source with the pinned Prettier configuration as part of lint. Documentation and generated files remain outside this first formatting scope to avoid unrelated rewrites.
- 2026-10-28: Evaluate hosting and database plans before provisioning them; account access and free-tier terms must be verified. See [ADR-001](adr/ADR-001-free-services.md).
- 2026-10-28: Keep design tokens in `packages/ui/src/theme.css` using Tailwind v4 `@theme` and override the same custom properties on `[data-theme='dark']`. Components therefore reference tokens by name and hold no hex values, and the gallery can show both themes on one page. Alternative rejected: a `dark:` utility for every component, which duplicates classes and makes the side-by-side gallery impossible.
- 2026-10-28: Resolve the theme and language on the server from cookies (`sd_theme`, `sd_locale`) instead of a client script or URL prefixes. The document is correct on the first byte, so there is no flash and no locale-specific routing to maintain. Alternative rejected for now: `/[locale]` segments, which would add redirects before the catalog has content in both languages.
- 2026-10-28: The gallery uses its own fixtures in `features/design/sampleData.ts` rather than pretending to be catalog data. They are labelled as design fixtures on the page and will be replaced by the seeded catalog in Phase 3; no product, vendor or order tables exist yet.
- 2026-10-28: Use Better Auth for sessions rather than a hand-written session table. It supplies password hashing, cookie handling, rate limiting and the organization plugin, and its MIT licence and self-hosted model satisfy the free-only policy. Alternative rejected: NextAuth, which would need custom organization and role work.
- 2026-10-28: Model platform roles as the eight values in `packages/domain/src/auth/roles.ts` and store them in the Better Auth `user.role` column. Permissions are a pure map in the domain package, so guards and tests share one source of truth. The admin plugin's ban and impersonation fields are kept, but its `admin` role is not used as the platform role.
- 2026-10-28: Use Prisma 7 with the `pg` driver adapter and keep the generated client out of Git. `prisma generate` runs before typecheck, build and seed. Migrations are generated as SQL locally and applied only by the `Database` GitHub Actions workflow, which uses the direct Neon URL; the app uses the pooled URL.
- 2026-10-28: Create the Better Auth instance lazily on the first request. A module-level instance opened Prisma during static page collection and logged `DatabaseNotConfiguredError` on every route; lazy creation keeps builds independent of a live database without weakening runtime checks.
- 2026-10-28: The public Try demo action accepts an allowlisted email only, signs in with `DEMO_ACCOUNT_PASSWORD` from the server environment, and reads the role from the database. It never accepts a role or user id from the browser. Demo accounts are flagged `isDemo` for future restrictions on email and password changes.
- 2026-10-28: The Phase 1 header links only to routes that exist (`/` and `/design`) plus the repository. Search, cart, account and the category mega menu get real destinations with their features in Phases 2 to 4, so the shell never ships a control that leads to a placeholder. The gallery demonstrates the mega menu against its own category list.
