# Decisions

- 2026-10-28: Start Phase 0 with a static, bilingual landing page and workspace quality gates. It does not require data loading, so no skeleton, empty state, or retry state is shown for this static content. Interactive localization and the design system remain Phase 1 work.
- 2026-10-28: Use ESLint 9.39.5 rather than ESLint 10 because the current Next.js plugins declare support only through ESLint 9; revisit when their peer ranges support the newer major version.
- 2026-10-28: Check formatting for web application source with the pinned Prettier configuration as part of lint. Documentation and generated files remain outside this first formatting scope to avoid unrelated rewrites.
- 2026-10-28: Evaluate hosting and database plans before provisioning them; account access and free-tier terms must be verified. See [ADR-001](adr/ADR-001-free-services.md).
- 2026-10-28: Keep design tokens in `packages/ui/src/theme.css` using Tailwind v4 `@theme` and override the same custom properties on `[data-theme='dark']`. Components therefore reference tokens by name and hold no hex values, and the gallery can show both themes on one page. Alternative rejected: a `dark:` utility for every component, which duplicates classes and makes the side-by-side gallery impossible.
- 2026-10-28: Resolve the theme and language on the server from cookies (`sd_theme`, `sd_locale`) instead of a client script or URL prefixes. The document is correct on the first byte, so there is no flash and no locale-specific routing to maintain. Alternative rejected for now: `/[locale]` segments, which would add redirects before the catalog has content in both languages.
- 2026-10-28: The gallery uses its own fixtures in `features/design/sampleData.ts` rather than pretending to be catalog data. They are labelled as design fixtures on the page and will be replaced by the seeded catalog in Phase 3; no product, vendor or order tables exist yet.
- 2026-10-28: Use Better Auth for sessions rather than a hand-written session table. It supplies password hashing, cookie handling, rate limiting and the organization plugin, and its MIT licence and self-hosted model satisfy the free-only policy. Alternative rejected: NextAuth, which would need custom organization and role work.
- 2026-10-28: Model platform roles as the eight values in `packages/domain/src/auth/roles.ts` and store them in the Better Auth `user.role` column. Permissions are a pure map in the domain package, so guards and tests share one source of truth. The admin plugin's ban and impersonation fields are kept, but its `admin` role is not used as the platform role.
- 2026-10-28: Use Prisma 7 with the `pg` driver adapter and keep the generated client out of Git. `prisma generate` runs before typecheck, build and seed. Migrations are generated as SQL locally and applied only by the `Database` GitHub Actions workflow, which uses the direct Neon URL; the app uses the pooled URL.
- 2026-10-28: Create the Better Auth instance lazily on the first request. A module-level instance opened Prisma during static page collection and logged `DatabaseNotConfiguredError` on every route; lazy creation keeps builds independent of a live database without weakening runtime checks.
- 2026-10-28: The public Try demo action accepts an allowlisted email only, signs in with `DEMO_ACCOUNT_PASSWORD` from the server environment, and reads the role from the database. It never accepts a role or user id from the browser. Demo accounts are flagged `isDemo` for future restrictions on email and password changes.
- 2026-10-28: The Phase 1 header links only to routes that exist (`/` and `/design`) plus the repository. Search, cart, account and the category mega menu get real destinations with their features in Phases 2 to 4, so the shell never ships a control that leads to a placeholder. The gallery demonstrates the mega menu against its own category list.
- 2026-10-28: Seed the Phase 3 catalog at 12 departments, 72 leaf categories, 24 vendors, 432 products and 1,296 variants, generated from curated inputs rather than hand-writing every row. The data specification targets 800+ products and 40+ vendors for the full simulation; those volumes belong with orders, reviews and payouts, when more rows actually exercise the product. The seed builder can add styles, colours or vendors without changing the schema.
- 2026-10-28: Keep listing price and stock on `products` as a denormalised summary of the default variant and the sum of variant stock. Filters and sorts then run without joining variants. The seed writes both in one pass; a future seller editor must update the summary and variants in the same transaction. Alternative rejected: aggregating variants in every listing query, which complicates pagination and sorting.
- 2026-10-28: Put product pages at `/product/[slug]` instead of under `/catalog/[slug]`. The product is a first-class page with its own metadata and JSON-LD, and the shorter path leaves `/catalog` for listing and filter URLs only.
- 2026-10-28: Search with a bounded `ILIKE` over English and Bangla titles and category names. Vendor names are excluded because they returned unrelated items for a craft query (a vendor named for jamdani matched every product in its store). PostgreSQL full-text search, trigram indexes and autosuggest are deferred to the search phase, when the fallback and ranking rules can be tested against a larger catalog.
- 2026-10-28: Paginate with `page` and a fixed page size of 12 rather than a cursor. Filters stay shareable and the page count is useful at this catalog size. Revisit with cursor pagination when the full seed or search ranking lands.
- 2026-10-28: Render product media as an original jamdani SVG with a tone per department instead of stock or generated photography. This avoids licensing, image hosting and a paid media budget before the media phase, and the pattern is sharp at every width. Product JSON-LD therefore has no image URL yet.
- 2026-10-28: Build the home department tiles from the live category tree, not the Phase 1 static list. The static list remains only in the design gallery as a fixture; a department change in the seed now appears on the home page without a second edit.
- 2026-10-28: Store guest carts in PostgreSQL behind a random HTTP-only `sd_cart` cookie, and signed-in carts by `userId`, rather than keeping guest carts in localStorage. The server can validate stock and prices for both, the cart survives a browser restart for 30 days, and the same drawer and actions serve both cases. A guest cart is merged into the user cart on sign-in. Alternative rejected: client-only guest carts, which would need a second pricing and stock path.
- 2026-10-28: Keep comparison in a small `sd_compare` cookie instead of a database table. It is a four-item browsing aid, must work signed-out, and is not worth a row per visitor. Wishlist is the opposite: it is durable and personal, so it lives in `wishlist_items` and requires a session.
- 2026-10-28: Keep checkout in the Next.js app with Server Actions instead of introducing the NestJS API before it has a consumer. The pure pricing, shipping and state-machine rules stay in `@sd/domain`, so a later API can reuse them; the browser still sends only ids and form fields, never a price. Alternative rejected for now: a second deployment with its own auth and CORS setup while the storefront is the only client.
- 2026-10-28: Charge one shipping fee per seller rather than one per order, using the destination district's zone. This matches the marketplace rule that each seller ships its own parcel. The drawer keeps its flat estimate and labels it as estimated; checkout is authoritative.
- 2026-10-28: Reserve stock by decrementing it with a conditional `UPDATE ... WHERE stock >= quantity` inside the order transaction, and record a `stock_reservations` row. The conditional update is the overselling guard; the reservation row carries status and expiry for the later cleanup job. Alternative rejected: a read-then-write stock check, which two concurrent checkouts can both pass.
- 2026-10-28: Make MockPay a first-class demo provider instead of a fake button. It issues a signed token with a 30-minute expiry and completes through the same callback endpoint a real gateway would use, so the idempotency path is exercised without a paid account. SSLCommerz and Stripe adapters wait for owner sandbox credentials.
- 2026-10-28: Store one coupon code on the cart and evaluate it on every read against the current rows, rather than storing a discount amount. A cart that drops below the minimum or loses the vendor's items then stops discounting instead of showing a stale total. Coupons are global or vendor-scoped, with percent in basis points, fixed poisha or free shipping; caps and minimums are integer fields. The demo supports one code per cart so the drawer never has to explain stacking. Alternative rejected: an in-memory coupon list, which would let a client see codes that the server has not activated.
- 2026-10-28: Use Next.js Server Actions for cart, wishlist and comparison writes rather than a REST route. The client only sends variant or product ids and a quantity; the action resolves the viewer, validates with Zod and re-reads stock. This keeps prices and ownership out of the request and avoids duplicating authorization in a second API layer.
- 2026-10-28: Keep cart totals in one pure `summariseCart` helper in `@sd/web` with integer poisha, a flat ৳120 delivery fee below ৳10,000 and free delivery at the threshold. It is the same function on the first render and after every action. Per-vendor shipping rates move into the Phase 5 checkout service.
- 2026-10-28: Sync server-rendered shop state into client controllers with a render-phase state adjustment (`useServerState`) instead of an effect. The adjust-on-prop-change pattern avoids a stale painted frame and satisfies the React compiler lint rule that rejects setState inside an effect.
