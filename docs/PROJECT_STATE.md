## Known issues

- There is no marketplace REST API or OpenAPI document. The only HTTP routes are Better Auth and the MockPay callback; every other write is a Server Action, as recorded in ADR-006 and [API.md](API.md).
- Search matches only English and Bangla product titles and leaf-category names. Descriptions, variants and vendor names are not searched; there is no typo tolerance, stemming or autosuggest yet.
- Product pages show the product's own photograph plus a gallery of two to four more, all sourced per product; there is no zoom or 360 view. Four hundred and forty photographs cover 142 publishable products, so 22 subcategories stay unpublished until more distinct photographs exist. Author and licence are listed in [CREDITS.md](CREDITS.md).
- Search ranking reorders at most 120 matches and never overrides an explicit price or rating sort. Byte tokenization has no stemming, Unicode normalization or autosuggest.
- The Python and Java modules run in CI only; a request uses the TypeScript port. The compiled WASM artifacts are regenerated by hand with `pnpm cs:build-wasm` and CI tests the committed bytes.
- Seeded reviews belong to synthetic demo buyers without login accounts. Reviewer names and bodies are seeded content, not real customers; the storefront names no viewer as a demo user.
- Review photos are bounded data URLs in PostgreSQL because no object-storage host is configured.
- Vendor staff can read the Seller Center but cannot write; staff permission sets arrive with staff management in a later phase.
- KYC is a text-only submission in this demo: there are no document uploads. Seeded stores start approved, so the admin queue shows only stores a seller has resubmitted.
- There is no new-store application flow; the Seller Center assumes the demo vendor already belongs to a seeded store.
- Bulk CSV import, packing-slip PDFs, seller replies to reviews, staff management, featured collections and a block-based store page builder are not implemented. CSV export is available.
- Seller analytics show ninety-day totals, best sellers and low stock without charts, a date-range picker or conversion metrics.
- Payouts are marked paid by the finance team; there is no bKash, Nagad or bank payout API and no settlement file. Refunds write a ledger transaction and a refund row, but no gateway refund is sent because payments are sandbox.
- The finance pages derive balances from every ledger entry in JavaScript. This is fine at demo volume; aggregate in SQL once transactions grow.
- There is no buyer-facing payment statement or downloadable ledger export yet.
- Listing pagination uses an offset `page` parameter; the specification's cursor pagination is deferred.
- The catalog seed is below the full data-spec target of 800+ products and 40+ vendors; see [decisions](DECISIONS.md).
- Vercel can queue production builds for several minutes, and a cache-miss build downloads the whole workspace, so it can spend minutes inside `pnpm install` before Next.js starts; cached rebuilds take about 15 seconds. See [DEPLOYMENT.md](DEPLOYMENT.md) for the build behaviour. A GitHub macOS runner can fail to acquire capacity (run 40724888199) without any code fault; rerun the job.
- Lint reports four existing `next/image` warnings for standard image elements; the images are locally stored and the current build remains within the asset budgets.
- axe and the six-width review were run by hand in a browser against production. There is no automated accessibility or visual-regression job yet; only Lighthouse runs in CI.
- Moderator and content editor production logins were not exercised individually; their role checks share the restricted admin branch verified with finance and are covered by unit tests.
- The CMS edits plain text with paragraphs split on blank lines; there is no rich text, embedded image, block layout or per-locale publish date. Feature flags cover only the Help Center and Journal, and the audit viewer has no action or actor filter and no export.
- Platform analytics are lifetime totals plus a 30-day delivered figure, without charts, date ranges, cohorts or conversion funnels.
- Rotating `DEMO_ACCOUNT_PASSWORD` requires re-running the seed workflow so existing demo passwords match.
- Cart totals are an estimate: the drawer uses a flat ৳120 below the free-delivery threshold, while checkout charges per seller by destination zone.
- MockPay reservations are held for 30 minutes but no scheduled job releases abandoned ones yet; a later job must restore stock and cancel the pending order.
- SSLCommerz sandbox and Stripe test mode are not wired because both need owner accounts and sandbox credentials. The checkout currently offers COD and MockPay only.
- Order emails are captured in the in-app outbox; no mail provider is configured.
