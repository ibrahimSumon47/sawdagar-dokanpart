## README.md (GitHub showcase)
Order: hero banner (original SVG/PNG) > badges (CI, Lighthouse, license, Next.js, TypeScript) > one-line pitch > live demo link > "Demo store: sandbox payments" notice > demo credentials table per role > screenshots and GIFs from `docs/screenshots` (light and dark, desktop and mobile) > why this project exists > features grouped by role > tech stack table with a "why chosen" column > CS fundamentals demonstrated table (module, language, concept, file path) > architecture diagram (Mermaid) > ER diagram (Mermaid) > repository structure > engineering challenges and how they were solved (stock integrity, ledger, idempotent webhooks, skeleton parity, free-tier design) > performance and test numbers > CI/CD overview > Deploy Your Own (Vercel button, env table; no "run locally" section) > known limitations > roadmap > skills demonstrated > license (MIT). Write in a natural engineering voice, specific and honest.

## AI-readable repository (recruiters use AI to review repos)
- `llms.txt` at the repo root AND served by the web app at `/llms.txt`: H1 title, blockquote summary, then sections linking to key docs and code.
- `docs/PROJECT_FACTS.json`: name, pitch, live URL, repository URL, roles, feature list with implementing file paths, stack with versions, test counts, coverage, Lighthouse scores, seed volumes, demo credentials, last updated. Generated by `scripts/gen-project-facts.mjs` and verified in CI.
- `docs/repo-map.md`: generated tree with a one-line purpose per folder (`scripts/gen-repo-map.mjs`).
- `AGENTS.md`, OpenAPI JSON at `/api/v1/openapi.json`, consistent README headings, `package.json` descriptions and keywords, GitHub topics.
- A public `/case-study` page with JSON-LD (`SoftwareSourceCode`), architecture diagram, decisions, challenges, metrics and links to the repository.
- Descriptive, searchable file and function names; TSDoc on public APIs.

## State file templates (create in Phase 0)
`docs/PROJECT_STATE.md` has sections: Done, Now, Next, Blocked, Known issues. `docs/REQUIREMENTS_LOG.md` is a table: date, owner instruction, status. `docs/LESSONS.md` is a list of "mistake > rule". `docs/DECISIONS.md` is a dated list of decisions with links to ADRs.
